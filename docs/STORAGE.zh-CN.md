# 存储与流式处理

[English](STORAGE.en.md) · 简体中文

Audience: public

Preview 和 Process 自动选择存储方式。已有工作流保留原连接与输出范围，不必增加配置节点。

## 默认上限

| 设置 | 默认值 | 行为 |
| --- | ---: | --- |
| 准备缓存总量 | 2 GiB | 准备或复用输入时，淘汰最久未使用的闲置条目。 |
| 单条输入缓存阈值 | 128 MiB | 原始颜色/运动估算超过阈值就流式处理，保留开关开启也不保存整段原始缓存。 |
| 临时任务总量 | 8 GiB | 当前占用加任务预算超过总量时，阻止新任务。 |
| 单任务临时预算 | 2 GiB | 包含编码后的预览、输出和任务日志。 |
| 磁盘最小剩余空间 | 2 GiB | 处理中检查；其他应用仍可能占用磁盘。 |

上限按当前 Comfy 实例的数据根目录共享，保存于 `storage-policy.json`，不影响输出时长或效果强度。
修改节点字段后需点击“应用上方空间上限”才会生效。任务预算是进程内管理，多个独立 Comfy
服务不要共用同一数据/临时根目录；磁盘检查不等于操作系统实际预留空间。

## 处理机制

小条目继续使用按内容与配置标识的准备缓存，只改 Look 可以复用颜色和光流。
“保留输入准备缓存”决定成功后是否保留小条目，但仍受总量限制。准备失败会移除未完成
的原始文件；已完成的准备条目可保留供失败重试。

大区间先扫描源视频时间戳，得到外部 Worker 要求的准确帧数。源视频因此解码两次，
扫描只留下小型时序描述，不保留像素。渲染时逐帧解码/颜色转换、计算光流、执行 NR，
把可见结果直接交给 FFmpeg。不存在整段颜色、光流或原始输出文件；编码器通过管道反压
限制上游速度。内存仍包含解码、光流、模型和编码器工作区，时序元数据随帧数增加但受协议帧数上限约束。

流式 Stack 的每层持有独立、连续初始化的 Worker，各层共享原始运动场和切镜标志，
颜色由前一层逐帧传给下一层。它能保持每层的时序历史并消除磁盘中间文件，但显存需求
比整段逐层处理高。多层 Worker 在任务结束后释放；单层可复用兼容常驻实例，超过常驻
流容量的任务使用隔离执行。Linux 各层 prefix 在后续任务间复用。

编码后的预览和输出仍会随时长及内容增长。FFmpeg 有文件大小上限，任务还会检查磁盘
余量与本次目录大小。截断输出无法通过帧数检查，不会发布为成功结果。编码包大小和检查
间隔可能导致少量超出，安全余量是额外缓冲，不是字节级文件系统配额。
当前大的裁剪/内存型 VIDEO 需要先保存再作为文件加载，因为公共 `VIDEO.save_to` 无法提供有界写入。

## 缓存与文件管理节点

添加 **DLSS 缓存与文件管理 / DLSS Storage Manager**，无需连线，界面在节点卡片内。
执行节点或点击刷新只读取列表，不会删除数据。

- 列出 `prepared-clips`、Comfy temp 下的 DLSS 任务，以及 `executions` 执行记录。
- 显示占用、路径、修改时间；展开条目查看其中的文件。
- 明确勾选并确认后，以完整条目为单位永久删除。
- 删除临时任务会使对应预览及未保存的 VIDEO 失效；先通过 Save Video 保存需要的结果。
- 渲染中禁用删除；列表过期后需刷新再删。
- 不删除源视频、正式输出、DLL、运行时快照或 Proton prefix；不扫描其他实例及旧数据根目录。
- 执行记录自动保留最近 1,000 个文件。临时预览任务不自动淘汰，到达配额后提示手动清理。

任务详情包含 `storage_plan`、`storage_usage` 和 `prepared_cache_retention`。
流式任务显示 `raw_disk_bytes: 0` 和 `streaming_no_prepared_cache`，表示没有原始帧落盘，
不表示编码视频及日志不占空间。
