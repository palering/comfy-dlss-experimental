# Interface localization

English · [简体中文](i18n.zh-CN.md)

Audience: public

The project supports **English (`en`)** and **Simplified Chinese (`zh`)**.
`zh-TW` currently reuses Simplified Chinese node text so the node card does
not become half-English; native Traditional Chinese wording can be contributed.

## Two localization layers

1. Standard node definitions use ComfyUI's official
   [custom-node i18n layout](https://docs.comfy.org/custom-nodes/i18n):
   `locales/<locale>/nodeDefs.json` translates node title, description, input
   and output captions, tooltips, and combo display labels.
2. The custom Preview, Input Adapter and Runtime Monitor DOM cards use the
   small modules in `web/i18n*.js`. They observe the same `Comfy.Locale`
   setting because custom frontend-component localization is not yet covered by
   the official node-definition catalog.

Some Nodes 2.0 versions translate field captions but not combo options. Our
display-only `getOptionLabel` adapter reads the same `/i18n` catalogs for those
options; it mutates only `getOptionLabel` in place, preserving the shared options
object, option array, selected value and callback.
The layout also follows the public
[ComfyUI i18n demo](https://github.com/comfyui-wiki/ComfyUI-i18n-demo) and
[Easy-Use catalogs](https://github.com/yolain/ComfyUI-Easy-Use/tree/main/locales).

The custom card catalogs use Chinese source messages and explicit English
translations. Tagged-template values are substituted literally into
`textContent`; arbitrary diagnostics are never evaluated or HTML-interpolated.

## Stable workflow contract

Translations must not change:

- node IDs, categories used by the backend, input/output socket IDs or types;
- combo **values**, numbers, booleans, paths, component hashes or JSON records;
- legacy caption-to-ID migration in `nr_look_choices.js`;
- cache keys or execution parameters.

`nodeDefs.json` option keys are the actual values and option values are only
visible labels. Do not replace old Chinese/bilingual combo values with English
machine values without a separate migration. Locale tests ensure the current
choice set remains exact.

Known structured media notices are localized in the card. Unknown worker,
Proton, FFmpeg and operating-system errors remain verbatim for debugging.
Copied task details intentionally keep paths, hashes, parameters and backend
identifiers unchanged.

## Adding a message

- For a standard node field, update both `locales/en/nodeDefs.json` and
  `locales/zh/nodeDefs.json`; mirror to `zh-TW` until it has a maintained
  native translation.
- For a custom-card string, wrap a plain source message with `t(...)` or a
  template with the `t\`...\`` tag, then add its English entry to
  `web/i18n_messages.js`. Use `bindText` only for static labels that need
  live language switching; dynamically rendered reports should rerender.
- Never translate user media names, local paths or unknown payload strings.
- Keep placeholders such as `{0}` identical between source and translation.

Run:

```bash
node --test tests/*.mjs
python3 -m unittest discover -s tests -v
```

The tests validate fallback behavior, literal interpolation, language switching,
catalog completeness, machine-value preservation and example workflow wiring.
After adding locale files to an installed custom node, restart ComfyUI and
refresh the browser.
